## Context

盈亏页在 `spork30/report.py`，只读 `state.json` 和成交日志。每局已有北京时间日期、状态、账面、剩余张数和停止原因。当天净额目前把所有已结束局加在一起，没有单独的亏损，也没有按日筛选。见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 在现有只读接口上增加所选北京时间日期的亏损、净盈亏、停止原因汇总和剩余代币列表。
- 日期列表覆盖状态文件里出现过的每一天，默认选今天。

**Non-Goals:**

- 不改引擎、风控、终端画面，不补记历史日志。
- 不估算返佣，不画图，不展示下单失败明细。

## Decisions

1. 账面以 `state.json` 为准，卖出均价仍从成交日志补。停止局的账面用回滚后的状态，不用日志里先记账再失败的中间数。
2. 日期取该局开盘时间的北京时间。当日亏损是所选日期里 `CLOSED` 且账面小于 0 的和；当天净盈亏是所选日期里全部 `CLOSED` 的和。未结束和已停止都不进入这两项。
3. 停止原因按所选日期、状态为已停止的局分组，组内给出局数和账面合计。没有停止原因的归到「未写明」。
4. 剩余涨或跌大于 0 的局，不论是否停止，都列入未兑付/未卖完列表。已结束但赢家一边已兑完、另一边尘埃为 0 的不列入。
5. 页面用日期按钮请求带日期的只读接口，明细表只返回该日的局。原有列保持不变。默认日期是北京时间的今天；今天没有局时仍显示 0，不自动跳到昨天。

备选是只在页面上用已返回的全部局自行汇总。不采用，因为刷新接口已经在服务端算账面，日期切换和汇总放在一起，避免两套口径。

## Risks / Trade-offs

- [已停止局的账面不是最终盈亏] → 不计入当日亏损，并在剩余代币列表里单独看见。
- [状态文件只保留本次进程见过的局] → 页面范围等于现有记录，不回补更早的日志。
- [重启盈亏页进程才会读到新代码] → 不需要重启下单进程。

## Migration Plan

改完后重启 `python -m spork30.report`。旧进程继续显示旧页面，停掉即可回到改前行为。
